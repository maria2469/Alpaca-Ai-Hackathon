03 Objectives and constraints

Built by a stock momentum trader who had never traded an option.

The operator

  • Trades stocks on momentum: gaps, breakouts, MACD turns on intraday bars.
  • No options experience. Greeks, assignment, pin risk: all new.
  • Limited screen time. The agent has to run itself and explain itself.
  • One week to build, three trading days to prove it.

The instrument: debit verticals

  • Max loss is the debit. Risk is known at entry, so sizing is one division.
  • Directional, like a stock trade, but capital-efficient: a $946 spread carried an $1,100 move in NVDA.
  • Defined width caps the upside, which makes a mechanical take-profit possible.
  • Both legs same expiry and type: no naked short, no early-assignment surprise on the debit side.

The objectives

  • Paper only. Startup aborts if the environment points anywhere but paper.
  • Small and reviewable: ten flat Python modules, every strategy number in one YAML file.
  • The AI decides direction only. Strikes, expiry, size, price and every exit are deterministic code.
  • When uncertain, no order. Passing is always acceptable.
Project rules in CLAUDE.md; methodology approved 2026-08-31, revised 2026-09-02 and 2026-09-03 (README.md).
04 System overview · one five-minute cycle

Exits first, then one directional decision, then code takes over.

Ten flat modules

settings · data_models · market_data · signals · options_screener · pos_and_risk · decision_layer · broker · cli · pnl. One orchestrator, cli.run_cycle. Only broker.py touches the environment or Alpaca.

One number file

Every threshold lives in settings.yaml, validated key-by-key at import. A typo'd key or an impossible combination stops every command before it can trade.

One way out

A single function submits orders. It re-validates the plan (two legs, ratio 1, day limit, paper) and is the only path from a decision to the broker. Dry run is the default; --execute arms it.

Mirrors the architecture section of README.md; module names are the real file names.
05 Component · entry signals

Momentum events on completed 5-minute bars, then a wall of gates.

Events (previous-bar ATR as the yardstick)

  • gap_up / gap_down: open jumps more than × ATR from the prior close.
  • breakout_up / breakout_down: a single bar's body exceeds × ATR.
  • macd_cross_up / down: histogram crosses zero and |hist| ≥ × ATR. Sub-threshold flips are chop, not momentum.

Gates, first failure wins

  • market_closed · stale_data (bar older than × 5 min) · insufficient_history (< bars)
  • missing_quote (spot quote absent or older than s against the broker clock) · no_event
  • rsi_exhausted: calls dropped at RSI ≥ , puts at ≤ . Exits still see the raw events: a capitulation gap must close a held position.
  • Held-position gates: pending_order, exiting, opposing_held.

What symbol-cycles ran into

Most cycles have nothing to decide. Only of symbol-cycles reached the decider. Trend EMAs (25 / 50) are shown to the decider as context but never gate.

signals.py · gate tally from every candidate in logs/cycles.jsonl · thresholds from settings.yaml.
06 Component · options screener

Turning "NVDA, calls" into two exact contracts.

1 · expiries
– DTEkeep only expiries with ≥ liquid strikes near spot, then the nearest
2 · strikes
OTM + the ATM bracketthe just-in-the-money strike is usually the tightest-quoted, highest-OI leg
3 · per leg
Liquidity and freshnessOI ≥ · bid/ask ≤ bps · quote within ± s of the broker clock · IV present
4 · width
– of spotsame rule sizes SPY and a $30 ETF
5 · debit band
– of widthkeeps the long leg near the money and reward:risk ≥ ~1.2. No lottery tickets.
6 · rank
Reward : risk, highest first(width − debit) / debit; ties go to the tighter combined bid/ask

Why picks die: leg and pair rejections to make orders

Every rejection is named

The screener returns a spread or a tally of why not, and the tally goes in the journal. That is how the 9/1 review found SPY alone had 925 too_narrow rejections: a 2% width floor was $15 on a $761 underlying. The floor became 1% the next morning.

A pick with no surviving spread is journaled as no_spread and costs nothing. of picks ended that way.

options_screener.py · docs/SPREAD_SELECTION.md · rejection tallies summed over every entry attempt in the journal.
07 Component · decision layer

The agent sees nine numbers per symbol and may answer with two words.

// the briefing, one object per gate-passing symbol
{ "symbol": "NVDA", "spot": 224.06,
  "events": [{ "kind": "macd_cross_up", "direction": "CALL" }],
  "rsi": 53.7, "atr": 1.10, "macd_hist": 0.078,
  "ema_fast_dist": 0.42, "ema_slow_dist": -0.35,
  "held": null }

// the only fields that matter in the reply
{ "action": "enter", "symbol": "NVDA", "direction": "CALL" }
// or: pass. Passing is always acceptable.

Who decided

Every live pick ( of ) was Claude, running the /paca-agent skill in Claude Code and piping its choice into cli.py run --manual-mode. An OpenRouter path with the same JSON contract exists and went unused. No chain data, no account, no P&L ever reaches the decider.

The rubric it trades by (from the skill)

  • A gap or breakout beyond 2 ATR is a strong impulse. A bare MACD cross is weak.
  • Bare crosses need a second leg to stand on: a same-bar gap or breakout, or price on the event's side of both EMAs with |hist|/ATR ≥ 0.10, or a stated higher-timeframe reason.
  • Never a second same-direction cross on the same symbol in a session.
  • A second entry in a cycle needs its own thesis. SPY then QQQ is one bet twice.
  • When uncertain, pass. No order beats a guessed order.

"The passes, which leaned on 'whipsaw', 'lower high', 'price above EMAs on a bearish cross', were right 22 times and never clearly wrong. The mechanical filters and the pass discipline carried the day; the discretionary entries did not."

08 Safety · the AI cannot bypass the code

of the agent's picks were killed by deterministic code after it chose them.

Guards between a pick and an order

  • Symbol must be one of the gate-passing candidates it was shown; direction exactly CALL or PUT; malformed JSON means no entry.
  • An add to a held underlying must match the held direction, whatever the decider said.
  • Screener veto (no_spread) · risk veto (risk_caps) · options level 3 re-read from the account.
  • Pre-submit re-check with a fresh clock, fresh account and fresh quotes: stale leg, wide leg, debit out of band, pending order on the symbol. Vetoed the same losing QQQ put two days running.
  • Exits never consult the decider. exits to date, all code-decided.

Guards around the account

  • Startup aborts unless ALPACA_PAPER=true and no live flag or live endpoint is set. paper=True is hardcoded in the client.
  • One submission function, whitelisted leg shapes, day limit orders only, nothing ever cancels or exercises automatically.
  • Deterministic client_order_id per cycle and spread, so a retry cannot double-fill.
  • Unknown equity or an unpairable leg means refuse, never estimate.
Funnel counts from logs/cycles.jsonl over every live cycle · guards in decision_layer.parse_entry_choice, cli._attempt_entry, broker.submit_paper_order, broker.load_config.
09 Component · risk management and position sizing

Four rooms, and the smallest one sets the size.

Caps, as fractions of live equity (re-read every cycle)

rooms = {
  per_entry:      0.5% × equity,
  per_underlying: 1.5% × equity − risk already on this name,
  per_cycle:      1.0% × equity − premium spent this cycle,
  total:          10%  × equity − open risk − spent this cycle,
}
qty = floor( min(rooms) / (net_debit × 100) )
# qty < 1 → refuse, naming the binding room
# unknown equity or open risk → refuse before any math

Premium at risk per trade

Contracts ranged 1 to 11 because the debit ranged 0.83 to 2.65 against the same $500 room. The cheap NVDA spread got the most contracts, and that is where the leverage came from.

Adding to a winner, safely

allow_stacking permits a same-direction add to a held underlying up to the 1.5% cap. The add never reuses a held leg: Alpaca nets positions per contract, so buying a strike we are short would unpair the held spread and put it beyond the exit manager. Per-cycle entries cap at floor(1.0% / 0.5%) = 2, decided one at a time.

pos_and_risk.size_entry · settings.yaml risk section · premium per trade from pnl.py realized (debit × qty × 100).
10 Component · exits and take-profit

Exits are mechanical, checked every cycle, and the agent is never asked.

1 · expiry
DTE ≤ signal-based, fires even on missing marks
2 · reversal
Opposing event firesa gap, breakout or qualified cross against the held direction
3 · stop
mark ≤ × debitdebit-relative on purpose: it frees the risk budget
4 · take-profit
mark ≥ min( × debit, × width)mark / width ≈ the market's probability of a full payoff

Why a width fraction

For a vertical, mark ÷ width is roughly the risk-neutral probability the spread finishes fully in the money. A fixed fraction therefore means the same remaining reward-to-risk on every spread: at 65% of width, 0.54 : 1. A debit multiple measures the entry price instead, and 3× is unreachable for any fill above 33% of width. The multiple stays only as a ceiling.

Exit reasons so far

The stop and the expiry exit have never fired. The reversal exit has closed every loser before it reached −50%, and one winner at +104%.

TSLA 375/380 call spread, Sep 18 expiry. Entered on a bare MACD cross the review graded "bad entry, chasing a bounce". Overnight it went to −21%, then to the short strike. Under the new rule the 65%-of-width target was 3.25; the mark was 2.43, so it held. Thirty seconds later a qualified macd_cross_down fired the reversal exit at 2.54.

13 What three days of paper taught the system

Every rule change has a date, a commit, and a journal fact behind it.

9/1 · pre-market to mid-day
Widths as % of spot, OTM-only, rank by reward:risk, caps tightened to 0.5% / 1.5%
Then four reversal-exit losses in a row, held 48 min to 2 h 46 m. Stop and take-profit never fired once.
9/2 · 09:36 · from the 9/1 review
MACD cross needs |hist| ≥ 0.05 ATR · RSI 70/30 entry gate · debit band 25–45% of width · width floor 1%
Bare sign flips had whipsawed every position. SPY alone: 925 too_narrow rejections. The ranker had bought an 11%-of-width TSLA lottery ticket.
9/2 · 10:17
Exit order ids get the strikes
Two AMZN call spreads exited in one cycle with identical ids; Alpaca filled one and refused the other. Self-healed a cycle later, then fixed.
9/2 · 11:17 → 12:19
Take-profit 2.0× → 3.5× → 3.0×
Nine minutes after NVDA filled at 2.06 the multiple went to 3.5×, then back to 3.0× "to let winners run a bit more".
9/2 · 12:13 → 12:34
Same-direction stacking · up to 2 entries per cycle
NVDA fired twice while held at 0.99% of equity and was gated already_held; the 1.5% per-underlying cap was unreachable.
9/3 · 09:07 · from the 9/2 review
Cancel CLI restored · stale spot quotes gated · every veto logged
The cancel loop was commented out and was needed once for real. GLD's IEX quote sat frozen at 400.66 for 2.5 hours and passed every gate.
9/3 · 11:03
Take-profit = min(3× debit, 0.65 × width)
Checked live against TSLA 375/380: target 3.25 vs mark 2.40, hold. Thirty seconds later the reversal exit banked it at 2.54.
The uncomfortable part. The biggest winner, NVDA 227.5/235 for +$1,320, was a bare MACD cross at 0.071 ATR on a debit of 11% of width. Today's system would not take it: the screener's 25%-of-width debit floor refuses the structure outright, and the decision rubric refuses a bare cross without a second leg. Both rules came out of the reviews anyway, because across all picks that pattern lost more often than it paid, and one outlier is not a rule. The system is tuned on the process, not on its best trade.

14 What comes next

Two changes the journal is already asking for.

1 · Regular-hours session filter

Indicators run on IEX bars that include pre- and post-market prints. Thin extended-hours bars shrink ATR, the yardstick every event is measured against, and the 09:30 "gap" compares against the previous extended-hours bar, so real overnight gaps are mostly invisible. Restricting market_data.fetch_ohlcv to 09:30–16:00 bars fixes both. Rated the highest-value remaining item in the review; deferred during the hackathon because it changes every signal at once.

2 · One decision per bar

A cycle runs every ~4.8 minutes, so the same completed 5-minute bar can be the "latest" bar twice, and one event can be acted on twice. WMT fired nine events inside a one-dollar range on 9/2. Recording acted-on (symbol, bar timestamp) pairs makes each event one-shot and removes a whole class of duplicate picks.

Later · greeks in the quote model

Delta on each leg unlocks a short-strike-delta take-profit and a delta-based entry filter, both studied and parked in docs/TAKE_PROFIT.md.

Later · 15-minute bars

Cleaner signals, far fewer trades. Deliberately kept at 5 m so the hackathon days produced enough decisions to grade.

Later · whitelist hygiene

WMT and MSFT fail the liquidity screen most and fire the most churn. /whitelist-candidates already probes replacements read-only.
